# Research pipeline (post-2026-10-21 snapshot)

The original October 21, 2026 dataset is immutable. `research.py` provides verification and **new, separately dated** observations from DefiLlama. It uses only Python 3.11+ standard-library modules and implements [Ponytail's minimal-change rules](https://github.com/DietrichGebert/ponytail/blob/main/skills/ponytail/SKILL.md), including tests for risky parsing and file-writing paths.

## 1. Verify original archive

```sh
python3 download_all.py /tmp/stablecoin-original
python3 research.py verify /tmp/stablecoin-original > quality-report.json
```

The verifier checks Git object hashes pinned in `manifest.json`, SHA-256 for reference, gzip/ZIP integrity, CSV row counts, header compatibility, malformed records and duplicate keys *when identifying columns are available*. A nonzero exit indicates errors. Check the JSON report. It validates file integrity and structural correctness, **not** truthfulness, absence of economic outliers, reserve backing, or coverage gaps. ZIP-member market records are not separately row-counted.

The original snapshots have intentionally missing `bridged_to_usd` values after asset index 215. Treat missing as unknown, never zero. The verifier may flag schema differences across these historical shards that require normalization.

## 2. Collect fresh historical observations

```sh
# USDT/USDC or other stablecoins: check current asset IDs in the catalog first
python3 research.py collect ./updates/2026-10-22 --assets 1,2 --market

# Comprehensive run. Hundreds of network calls, check upstream rate limits.
python3 research.py collect ./updates/full-2026-10-22 --all-assets --market
```

The collector retrieves the upstream current asset catalog and selected `/stablecoin/{id}` histories. Each request is preserved as gzipped JSON with its URL and SHA-256 in `snapshot.json`. The normalized `asset_chain_daily.csv.gz` is keyed by `(stablecoin_id, chain, date, peg_type)` and keeps circulation in peg units separate from USD. Unknown values stay empty. Schema errors, invalid IDs and duplicates fail the run without publishing a partial output directory. Existing snapshots are never overwritten.

With `--market` it also captures `/stablecoincharts/all`, `/stablecoinchains`, and `/stablecoinprices`, writing `market_daily.csv.gz`, `price_daily.csv.gz`, and `price_key_mapping.csv`. Price keys match the current catalog **only through unique exact `gecko_id` values**. Ambiguous/unmatched keys remain explicitly flagged, not guessed. Matches are *current* metadata and are not point-in-time asset identities.

**Caveats:** This fetches provider-revised *histories*. Collecting tomorrow can change yesterday's figures. Each capture is an observation vintage. Chain circulation is not transfer volume, minted measures are not proven primary issuance/redemption flows, and no reserve attestations are ingested. You need independent sources for economic conclusions.

## 3. Automatically run test and snapshot workflows

The repository CI now runs parser and join tests. `stablecoin-research.yml` runs a daily **targeted** collection of IDs 1 and 2 plus aggregate market and historical prices, storing an artifact for 90 days. It can also be dispatched manually for the complete catalog. The workflow only becomes scheduled after it is merged into the **default branch** and GitHub Actions is enabled. GitHub Artifacts are expiring snapshots, not permanent source archives. For durable retention, publish outputs to versioned object storage or a release archive with a policy that handles upstream licensing and size.

Run tests locally:

```sh
python3 -m unittest discover -s stablecoin-history/2026-10-21 -p 'test_*.py' -v
```

## 4. Next data products that require new source access

1. Independently dated issuer reserve reports. Separate cash, Treasury bills, repos, crypto collateral, other assets, and reporting period from publication date.
2. Verified mint/redeem and transfer flows. Distinguish bridge movements from real issuance and double-counting.
3. Treasury issuance, yields, ownership and international holding records. Separate correlation from causation, and issuer holdings from foreign owner identities.
4. Historical issuer/contract crosswalk and stablecoin lifecycle events. Current Gecko IDs alone cannot establish historical identity.

No unverified reserve holdings or blockchain transfers are generated by this pipeline.
